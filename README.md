# dotfiles

Omarchy (Arch + Hyprland) configuration, managed with GNU Stow.

## Bootstrap a new machine

```bash
git clone <this-repo> ~/dotfiles
~/dotfiles/install.sh              # symlinks + themes + plugins + systemd units
~/dotfiles/install.sh --packages   # ...and reinstall every package too
```

## Layout

Each top-level directory is a stow package mirroring `$HOME`:

| Package | Contents |
|---|---|
| `hypr/` | `~/.config/hypr/*.lua`, `hyprsunset.conf`, `xdph.conf` |
| `omarchy/` | `shell.json`, `shell.toml`, `extensions/`, `hooks/`, `branding/`, `backgrounds/` |
| `terminals/` | alacritty, foot, kitty, ghostty |
| `shell/` | `.zshrc`, `.zprofile`, `.zshenv`, `.p10k.zsh`, `.bashrc`, `.gitconfig` |
| `bin/` | hand-written scripts in `~/.local/bin` |
| `systemd/` | user unit files (enable state lives in `manifest/`) |
| `apps/` | btop, lazygit, nvim, git, tmux, fastfetch, starship, mimeapps |
| `manifest/` | package lists, theme/plugin git remotes, systemd enable/mask state |

## Two kinds of systemd unit

**Hand-written units** (`calibre-server`, `voxtype`, the nightlight timers,
`omaprayers-syncloc`) live as real files in `~/.config/systemd/user/`, so
they're moved into `systemd/.config/systemd/user/` and stowed like everything
else. `install.sh` enables these by reading the files themselves.

**Packaged units** (`syncthing.service`, `bt-agent.service`,
`wireplumber.service`, …) ship inside their package at
`/usr/lib/systemd/user/` — there's no local file to stow, only an on/off
state. These are tracked purely as names in `manifest/systemd-enabled.txt`
(regenerated by `sync.sh`), and `install.sh` reads that file and
`systemctl --user enable --now`s each one. This is what makes enabling
Syncthing on a new machine (`pacman -S syncthing` + `install.sh`) actually
turn it on, instead of the manifest being a write-only record nobody reads.

## Why `--no-folding`

`.stowrc` pins `--no-folding`. This is load-bearing, not cosmetic.

Without it, Stow collapses `~/.config/hypr` into a *single symlink* pointing at
this repo. Omarchy then drops its `*.bak.<timestamp>` files — which it creates
on every config rewrite during an update — directly inside the repo as untracked
junk. With `--no-folding`, `~/.config/hypr` stays a real directory holding
per-file symlinks, and Omarchy's backups stay outside version control.

## Deliberately NOT tracked

- **`~/.config/omarchy/themes/`** and **`plugins/`** — upstream git clones (~750M).
  Tracked by URL in `manifest/`, re-cloned by `install.sh`.
- **`~/.config/hypr/shaders/`** — 138 symlinks into `/usr/share/aether/`, package-owned.
- **`~/.config/btop/themes/current.theme`** and **`~/.config/nvim/lua/plugins/theme.lua`** —
  generated/rewritten live by Omarchy theme switching (they're symlinks into
  `~/.local/state/omarchy/current/theme/`, recreated on every `omarchy theme set`).
- **mise shims** in `~/.local/bin` (`claude`, `gh`, `codex`, …) — regenerated by mise.
- **`*.sample` hook files** — shipped by the omarchy package.
- Browser profiles, 1Password, Steam, Signal, credentials — app state and secrets.

## Theme overlay fixes (`manifest/theme-overlays/`)

Sometimes a stock Omarchy theme has a bug (e.g. the built-in `catppuccin`
theme's `neovim.lua` sets `colorscheme = "catppuccin-nvim"`, which doesn't
exist — every other theme uses its plugin's real registered name like
`gruvbox` or `kanagawa`). The documented fix is a same-slug overlay directory
under `~/.config/omarchy/themes/<name>/` containing just the files to patch.

**These overlay files must be plain files, never symlinks.** `omarchy theme
set` builds its staged theme with `cp -r "$USER_THEMES_PATH/$THEME/"*
"$NEXT_THEME_PATH/"`, which copies a symlink as a symlink instead of following
it — a stowed symlink lands one directory deeper than it expects, dangles, and
breaks theme-set entirely (confirmed the hard way fixing the catppuccin
overlay below).

So overlay masters live as real files in `manifest/theme-overlays/<name>/`
(not stowed) and `install.sh` `cp`s them into `~/.config/omarchy/themes/<name>/`
on every run. **After editing one, redeploy it manually:**

```bash
cp manifest/theme-overlays/catppuccin/neovim.lua ~/.config/omarchy/themes/catppuccin/
omarchy theme set catppuccin
```

## How this survives `omarchy update`

Omarchy only writes to files it owns under `~/.config/`, and backs them up first.
Because those files are symlinks into this repo, an update that rewrites one
shows up as a `git diff` rather than silently replacing your version.

`omarchy/.config/omarchy/hooks/post-update.d/dotfiles-drift.hook` runs after
every update: it re-stows anything that got replaced by a real file and sends a
notification if the repo drifted.

```bash
git -C ~/dotfiles diff        # see what the update changed
git -C ~/dotfiles checkout .  # keep your version
git -C ~/dotfiles commit -am "Adopt new upstream defaults"  # take theirs
```

## Refresh the manifests

```bash
~/dotfiles/sync.sh
```
